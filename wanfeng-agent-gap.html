一句话结论：目标文档描述的是一套六层能力齐备的「金融 Agent 操作系统」；代码里实际存在的是一个契约先行、治理扎实、但数据面与产品面尚未接通的工程底座。

在 18 万行 Python、143 个测试文件、3,875 条用例的工程量里，真正跑在生产路径上的只有 Agent Runtime 与 治理三件套（RBAC／审批／审计），外加一条 A 股分钟数据研究链路。目标文档的三大核心指标与「跨 A/H/US」「行业轮动」「策略蒸馏」「知识库 Memory」，在代码里要么被显式关闭、要么硬编码为 unavailable、要么背后根本没有数据。

一、六层能力逐层判定

目标能力代码实态判定
① 主动式 Agent Runtime 真 ReAct 循环（agent_model_loop.py，max_iterations=8、原生 tool_calls + 文本 JSON 回退、错误回灌）；真持久化队列（SQLite WAL BEGIN IMMEDIATE / PG FOR UPDATE SKIP LOCKED、租约+心跳+退避+死信）；真 SSE（逐 token delta、事件落库、cursor 续传）；注册 46 个工具 生产级
② 财富配置 AGENT_FOLIO_PORT = DisabledFolioPort()，docstring 原文：“Fail-closed placeholder while private Folio data ingestion is unavailable.” 契约层硬编码 attribution: HISTORICAL_SNAPSHOT_NOT_ACCEPTED、sector_exposure: P14_NOT_ACCEPTED；performance.py 直接返回占位串 "pending_industry_history"；再平衡「求解器」是逐 bp 削顶循环（只能减不能加）。真实可用的只有 legacy 基金净值分析，自标 nav_based_proxy_not_trade_attribution 空壳
③ 市场与个股研究 markets／sectors／equities 三域全部 enabled=False + 零 IO 网关（调用即 AssertionError("disabled markets Gateway must remain unreachable")）。rotation 是过形状校验的 blob，从不计算；7 个 section 共用一个「公式」= 5 键小数位配置。数据只覆盖 1 个交易日、只有 sh/hk 两个市场 → 轮动在结构上不可能 空壳
④ 主观策略蒸馏 llm_distiller.py 的因子是硬编码字面量（"0.35*zscore(momentum_20d)+…"），backtest_logic_python 引用不存在的字段且从不被编译执行；策略版本 = 一行 JSON；「回测引擎」engine.py 吃外部预算好的 NAV CSV，不做信号与撮合；真实的因子引擎（IC/ICIR/分层/GP）藏在 incubator/ 且平台从不调用 空壳
⑤ 知识库与 Memory Memory 是每会话一个 JSON ring buffer，prefetch(query) 根本不使用 query；无向量、无跨会话、无冲突消解；会议纪要零代码。项目自己的 knowledge_asset_registry.json 把研报库／私域 Memory 标为 missing + blocked。唯一真实的是定时调度器 空壳
⑥ 金融级治理 RBAC 逐 173 条路由核验真实执行（中间件 + 依赖注入双层）、租户隔离完整、审批是执行前真 gate 且参数哈希绑定不可换参重放、沙箱 AST 白名单真实。缺口：审计无防篡改（无哈希链／WORM） 准生产

二、目标文档里逐条对不上的宣称

1核心指标是落地页的硬编码 HTML

100亿+ 数据行级资产 / 50,000+ 研究任务 / 1,000+ 策略版本 —— 与仓库 landing/index.html:69-71 完全一致，无任何数据绑定。

仓库里 data/ 只有一个 104KB 的分类树 JSON，无数据文件、无 manifest、无统计输出。项目自己的发布说明写的真实规模是「日线缓存 144 行、8 只标的」。

2技术栈五缺二

PostgreSQL 真 · SSE 真 · MongoDB 适配器真但未接运行时。

DuckDB 全仓零代码（还有一个测试专门断言不许 import 它）；pgvector 全仓零使用——唯一痕迹是 knowledge_assets.py:19 一个 "vector_index" 枚举字符串和落地页文案。

3跨 A/H/US 不存在

港股 / 美股 / nasdaq / nyse 在 Python 里零命中；美股只有 SEC 当日公告。所谓「映射到同一个研究空间」只存在于 InstrumentId 身份层，数据层没有统一 schema。

数据实况：sector／ticker 快照仅 1 个交易日、仅 sh / hk 两个市场；231 个 L3 分组每组恰好 1 个观测。

4「可复算事实」基本不成立

全库无 recompute / verify / replay；有的是内容寻址哈希——能发现篡改，不能重算数值。唯一真正可复算的是 69 行的 FinancialSelectionReceipt。

5「0 黑箱」是文档里兑现得最好的一句

A 股链路真的建模了 evidence / execution_path（6 步）/ limitations / private_reasoning_exposed=False。

但边界在 API 层破了：GET /api/agent/runs/{id} 会原样返回 thought 字段，「不展示思维链」只在 UI 渲染层成立。

四、最值得警惕的：不是「没做完」，而是「做成了两套」

现象证据
两套并行数据访问严格契约版适配器（envelope／质量门／血缘，341 个测试真通过）只在测试里被调用；server.py 运行时另有一套内联 pymysql.connect() / MongoClient()（5+ 处），绕过全部契约
契约层是「可执行规格书」agent_sectors_contracts.py 5,171 行中约 88% 是 schema／校验／常量，真业务逻辑 0%；*_contracts.py 合计 23,008 行，占 quant_engine 约 30%
工具注册表宣称了被禁用的能力46 个 canonical 工具含 agent_markets_* / agent_folio_*，模型能看到、能调用，但会撞上 enabled=False 网关抛异常
CI 不跑产品测试3 个 workflow 全是治理（建 Issue、状态投影、仓库策略），只跑 6 个测试文件 + compileall；仓库有 143 个测试文件
量化核心完全无测试grep -rln "BACKTEST_ENGINE\|run_nav_backtest\|ExecutionModel" tests/ → 零命中

五、真正做出来了的

  1. Agent Runtime —— 真循环 + 持久化队列 + 逐 token SSE + 审批／审计／沙箱。这是整个仓库最有价值的资产，也是唯一经得起「生产级」三字的层。
  2. A 股研究链路 —— 真实只读接入 MySQL base_realtime（5,223 只证券分钟数据）与 Mongo His_TICK_V2，真实 DeepSeek run 成功过（f08c7fb0…）。
  3. 治理三件套 —— RBAC（173 路由核验）／执行前审批（参数哈希绑定）／step 级审计。
  4. 工程质量 —— fail-closed 默认、source_writes=0 只读硬门、内容寻址、PIT／vintage、rights gating、0 个 TODO、独立 Review／QA 制度。

6.1 项目所谓「全量」只是 63 个文件的手工清单

RELEASE_NOTES.md 里那句「默认全量：479 passed」，对应的清单在 scripts/agent_regression.py:279 起，是逐行枚举的 63 个测试文件。仓库有 143 个，80 个不在发布回归门内，其中包括：

  • 整个数据层：test_agent_data_mysql / data_mongo / data_contracts / data_reference / data_public
  • 整个领域层：test_agent_equities_*、test_agent_equity_attribution、test_agent_folio_*、test_agent_domain_server_adapters
  • A 股链路：test_agent_a_share_live_server、test_agent_a_share_live_service、test_agent_a_share_market_bridge

被排除的恰好就是那些「未接线 / enabled=False」的能力域。发布门只覆盖接上线的部分——逻辑自洽，但意味着「测试全绿」覆盖不到六层里的四层。

八、方法、边界与可复核性

  • 分析对象：GitHub 上的 wanfeng-agent-platform 源码快照（361 个 .py、180,667 行 Python）。分析在独立目录内完成，未修改被分析的代码。
  • 判定口径：区分三种状态——「有 schema／契约定义」「有真实计算实现」「在运行时被接线且可用」。仅在运行时被接线并真正执行的才算「可用」。表格中的「空壳」指前两者存在、第三者缺失。
  • 测试复跑：在 macOS + Python 3.12 独立虚拟环境安装 requirements-agent.txt 全部依赖后，对仓库全部 143 个测试文件执行 pytest，得到 8 failed / 3827 passed / 40 skipped。项目声明的目标平台是 Windows，故门内 2 个平台相关失败在其目标平台上预期为通过。
  • 未覆盖：本分析基于静态源码与测试复跑，未连接生产数据库（Mongo His_TICK_V2、MySQL base_realtime）、未调用真实模型供应商、未部署运行。涉及「真实数据规模」的结论以代码内自述与快照元数据为准，未经生产环境验证。
  • 结论时效：基于 2026-09-11 的源码快照；项目处于活跃开发中，结论可能随后续提交变化。
